# Лабораторная работа №8. AI-автоматизация DevOps-процессов

## 1. Цель работы

Разработать автоматизированного помощника DevOps-инженера для анализа алертов мониторинга с использованием n8n, AI-агента и MCP-серверов. Настроить мониторинг системы с помощью Prometheus и Grafana.

## 2. Описание проекта

Разработан **DevOps Alert Assistant** — AI-помощник для первоначальной диагностики инцидентов.

При получении алерта агент запрашивает дополнительные сведения о сервере через MCP-инструменты, анализирует метрики и журналы приложения, после чего формирует рекомендации DevOps-инженеру.

В качестве тестового сценария используется высокая загрузка CPU (95%) на сервере `web-server-01`.

**Используемые технологии:** Docker, Docker Compose, n8n, OpenRouter, Python, FastMCP, Prometheus, Grafana.

## 3. Архитектура решения

Workflow состоит из следующих компонентов:

1. **Manual Trigger** — запуск сценария.
2. **Read/Write Files from Disk + Extract From File** — загрузка Skill.
3. **Edit Fields** — формирование тестового алерта.
4. **AI Agent + OpenRouter** — анализ инцидента.
5. **Два MCP-сервера** — предоставление диагностических данных.

### MCP-серверы и Toolkit

Реализованы два независимых MCP-сервера и четыре инструмента:

| MCP-сервер | Инструмент | Назначение |
|---|---|---|
| Metrics | `get_server_metrics` | Получение CPU, RAM и состояния сервера |
| Metrics | `get_top_processes` | Получение списка процессов |
| Logs | `get_service_logs` | Получение журналов приложения |
| Logs | `search_errors` | Поиск ошибок в журналах |

Оба сервера используют учебные данные и взаимодействуют с n8n по протоколу MCP.

### Skills

Создан файл `skills/alert-triage.md`, содержащий алгоритм диагностики и правила работы AI-агента.

Skill определяет порядок использования MCP-инструментов, правила сопоставления метрик и логов, а также формат итогового ответа.

Агент не изменяет инфраструктуру самостоятельно, а только предлагает рекомендации DevOps-инженеру.

## 4. Запуск проекта

Клонировать репозиторий и перейти в папку лабораторной:

```bash
git clone -b lab_8 https://github.com/NorthPole0499/DevOps-Frog-2026.git
cd DevOps-Frog-2026/lab_8
```

Запустить контейнеры:

```bash
docker compose up -d --build
```

Проверить состояние:

```bash
docker compose ps
```

В учебном окружении использовался локальный сертификат Kaspersky для HTTPS-соединений. Он не включён в репозиторий. При запуске на другой машине необходимо удалить соответствующее подключение `pki` из Docker Compose либо настроить собственный доверенный сертификат.

После запуска доступны следующие интерфейсы:

| Сервис | Адрес |
|---|---|
| n8n | http://localhost:5678 |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3000 |

В n8n необходимо импортировать `n8n/devops-alert-assistant.json`, настроить OpenRouter со своим API-ключом и выбрать доступную языковую модель.

## 5. Результаты тестирования

Для проверки работы системы был создан тестовый алерт `HighCPUUsage` с загрузкой процессора 95%.

AI-агент успешно использовал инструменты обоих MCP-серверов и получил следующие данные:

- CPU сервера — 95%.
- RAM — 72%.
- Процесс `python` использует 83% CPU.
- В журналах обнаружены ошибки выполнения фоновой задачи.

На основании этих данных агент определил вероятную причину высокой нагрузки и сформировал рекомендации по диагностике и оптимизации процесса.

### Обоснование алертов

| Алерт | Условие | Назначение |
|---|---|---|
| N8N Service Down | Недоступность n8n более 1 минуты | Контроль доступности автоматизации |
| Slow Alert Processing | Среднее время выполнения более 15 секунд в течение 5 минут | Обнаружение задержек |
| MCP Tool Errors | Более 0 ошибок за 5 минут | Выявление проблем с инструментами |

В Grafana реализован алерт `N8N Service Down`. Остальные два обоснованы как возможные правила мониторинга.
