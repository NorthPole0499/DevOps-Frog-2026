\# Лабораторная работа №8. AI-автоматизация DevOps-процессов



\## 1. Цель работы



Разработать автоматизированного помощника DevOps-инженера для анализа алертов мониторинга с использованием n8n, AI-агента и MCP-серверов. Настроить мониторинг разработанной системы с помощью Prometheus и Grafana.



\## 2. Описание сценария



В процессе эксплуатации веб-приложений DevOps-инженеры сталкиваются с алертами мониторинга, которые требуют дополнительной диагностики.



Для автоматизации первоначального анализа инцидентов был разработан AI-помощник, который получает информацию об алерте, обращается к диагностическим инструментам и формирует рекомендации по устранению проблемы.



В лабораторной используется тестовый сценарий высокой загрузки CPU сервера `web-server-01` до 95%.



\## 3. Используемые технологии



\- Docker и Docker Compose — контейнеризация сервисов.

\- n8n — создание и выполнение workflow.

\- OpenRouter — подключение языковой модели.

\- FastMCP — реализация MCP-серверов.

\- Python — реализация диагностических инструментов.

\- Prometheus — сбор метрик.

\- Grafana — визуализация и мониторинг.



\## 4. Архитектура решения



Workflow состоит из следующих этапов:



1\. Manual Trigger запускает процесс.

2\. Read/Write Files from Disk считывает Skill.

3\. Extract From File преобразует инструкции в текст.

4\. Edit Fields формирует тестовый алерт.

5\. AI Agent получает данные алерта и инструкции Skill.

6\. AI Agent обращается к двум MCP-серверам.

7\. На основе полученных данных формируется диагностический отчёт.



\### MCP Metrics



Сервер предоставляет инструменты:



\- `get\_server\_metrics` — получение загрузки CPU, RAM и состояния сервера.

\- `get\_top\_processes` — получение списка процессов с наибольшей загрузкой CPU.



\### MCP Logs



Сервер предоставляет инструменты:



\- `get\_service\_logs` — получение журналов приложения.

\- `search\_errors` — поиск ошибок в журналах.



Оба MCP-сервера работают с учебными данными.



\## 5. Skill



Создан файл `skills/alert-triage.md`, содержащий алгоритм диагностики инцидентов.



Skill определяет последовательность вызова инструментов, правила анализа информации, требования к формату ответа и ограничения безопасности.



AI-агент не выполняет автоматическую остановку или перезапуск сервисов, а предоставляет рекомендации DevOps-инженеру.



\## 6. Результаты тестирования



Для проверки системы был сформирован тестовый алерт `HighCPUUsage` с критическим уровнем и загрузкой CPU 95%.



AI-агент успешно получил метрики и журналы приложения через MCP-серверы.



В ходе анализа был обнаружен процесс `python` с высокой загрузкой CPU и сообщения журнала о продолжительном выполнении фоновой задачи.



На основании полученных данных AI-агент сформировал рекомендации по диагностике и устранению проблемы.



\## 7. Мониторинг



Для контроля работы автоматизации были развёрнуты Prometheus и Grafana.



Создан дашборд `DevOps Alert Assistant Monitoring` с тремя графиками:



1\. Количество выполнений workflow.

2\. Средняя длительность выполнения workflow.

3\. Количество ошибок вызова AI-инструментов.



\### Обоснование алертов



| Алерт | Условие | Назначение |

|---|---|---|

| N8N Service Down | `up{job="n8n"} < 1` в течение 1 минуты | Обнаружение недоступности платформы |

| Slow Alert Processing | Средняя длительность более 15 секунд в течение 5 минут | Выявление задержек обработки |

| MCP Tool Errors | Ошибки вызовов AI-инструментов за 5 минут > 0 | Обнаружение проблем диагностических инструментов |



Первый алерт реализован в Grafana. Остальные два предложены для возможного внедрения.



\## 8. Вывод



В ходе лабораторной работы был разработан AI-помощник DevOps-инженера для автоматизированного анализа алертов мониторинга.



Были настроены n8n, языковая модель, два MCP-сервера с четырьмя инструментами и Skill для управления алгоритмом диагностики.



Также была развёрнута система мониторинга Prometheus и Grafana, позволяющая контролировать выполнение автоматизации и отслеживать ошибки.


## 9. Инструкция по запуску

### Требования

Для запуска лабораторной необходимо установить:

- Docker Desktop с поддержкой Docker Compose;
- Git;
- браузер для работы с веб-интерфейсами;
- API-ключ OpenRouter для использования языковой модели.

### Запуск контейнеров

Клонировать репозиторий:

```bash
git clone https://github.com/NorthPole0499/DevOps-Frog-2026.git
cd DevOps-Frog-2026/lab_8
```

Перед запуском необходимо проверить настройки `docker-compose.yml`.

В учебном окружении использовался сертификат Kaspersky, подключённый через папку `pki`. Сертификат является локальным и не публикуется в GitHub. При отсутствии HTTPS-перехвата соответствующее подключение сертификата можно убрать из Docker Compose.

Запустить сервисы:

```bash
docker compose up -d --build
```

Проверить состояние:

```bash
docker compose ps
```

После запуска доступны следующие интерфейсы:

| Сервис | Адрес |
|---|---|
| n8n | http://localhost:5678 |
| Prometheus | http://localhost:9090 |
| Grafana | http://localhost:3000 |

### Настройка AI-агента

1. Открыть n8n.
2. Импортировать файл `n8n/devops-alert-assistant.json`.
3. Настроить подключение OpenRouter с собственным API-ключом.
4. Выбрать доступную языковую модель.
5. Проверить подключения к MCP-серверам.
6. Выполнить workflow с тестовым алертом.

Адреса MCP-серверов внутри сети Docker:

- Metrics: `http://mcp-metrics:8000/mcp`
- Logs: `http://mcp-logs:8000/mcp`

### Проверка мониторинга

В Prometheus открыть страницу `/targets` и убедиться, что задания `prometheus` и `n8n` имеют состояние `UP`.

В Grafana подключить Prometheus по адресу `http://prometheus:9090` и создать панели с запросами, описанными в разделе мониторинга.

## 10. Ограничения реализации

В лабораторной используются тестовые показатели серверов и заранее подготовленные журналы приложения. Данные не относятся к реальной инфраструктуре.

AI-агент выполняет первичную диагностику и формирует рекомендации, но не изменяет состояние серверов автоматически.

Автоматическое получение алертов из настоящей системы мониторинга не реализовано. Для учебного тестирования используется ручной запуск workflow.
